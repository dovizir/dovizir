# @dovizir/notes-acceptance — referee suite

Referee vitest acceptance suite for the pure-TS `@dovizir/notes` library
(dual-build experiment, round 1 — see `docs/experiment/PROTOCOL.md`). The
frozen API both arms implement is `notes-api.d.ts` in this directory. Specs
import the implementation **only** through the `@dovizir/notes` alias and use
`@noble/curves` / `@noble/hashes` to build expected values independently.

## Running against an arm

```sh
cd packages/acceptance/notes
pnpm install            # if pnpm complains about the workspace root, use: pnpm install --ignore-workspace
DOVIZIR_NOTES_IMPL=/abs/path/to/arm/packages/notes/dist/index.js pnpm vitest run
```

`DOVIZIR_NOTES_IMPL` must point at the arm's built ESM entry **module** (a
file vite can resolve, e.g. `dist/index.js`; a TS source entry also works
since vitest transforms it). Relative paths are resolved from the directory
you run vitest in. Without the variable, the alias falls back to
`impl-missing.ts` and every spec file fails with
`no implementation aliased` — that is the expected no-arm behavior, not a
suite bug.

## Layout

- `notes-api.d.ts` — the frozen interface (read-only; referee ground truth).
- `vitest.config.ts` — the alias wiring described above.
- `specs/*.spec.ts` — acceptance specs by area (canonicalize, keys, carve,
  invoice, spend/verify, verify reasons, certs, reconcile, one-hop, goldens).
- `specs/support/` — noble-based helpers + deterministic fixtures. Fixture
  key pairs are literals derived with noble, never via `generateKeyPair`.
- `goldens/*.golden.json` — committed byte-exact wire-format expectations,
  generated by `pnpm gen:goldens` (`tools/gen-goldens.mjs`) from noble
  primitives only. Regenerate only on a sanctioned wire-format change and log
  it in EXPERIMENT-LOG.md.

## Pinned interpretations (referee decisions on API ambiguities)

The frozen `.d.ts` leaves gaps; the suite pins them as follows. Under the
protocol's spec-bug rule (§5), if both arms trip over the same pin it gets
re-adjudicated.

1. **Canonical bigints**: minimal lowercase `0x`-hex; `0n` → `"0x0"`.
2. **Optional fields**: `undefined`/absent fields are omitted from canonical
   JSON (no `null` placeholders).
3. **Byte strings**: values matching `^0x[0-9a-fA-F]+$` are lowercased;
   other strings serialize per `JSON.stringify` with raw UTF-8 (no `\u`
   escaping of non-ASCII).
4. **Merkle tree**: leaf = `keccak256(serial ‖ uint256-be(value))`; serial =
   `keccak256(batchSalt ‖ uint32-be(index))`; interior nodes are
   *commutative sorted-pair* keccak (OpenZeppelin `MerkleProof` compatible).
   Single-note batch: root == leaf, empty proof. Odd leaf counts are NOT
   pinned — goldens/fixtures use power-of-two batches.
5. **Signatures**: 64-byte compact `r‖s`, RFC6979 deterministic, low-s
   (noble defaults) — pinned byte-exact by the goldens.
6. **Expiry boundary**: valid iff `now < expiry`, for certs (mandated) and
   notes (extended for consistency); `now == expiry` is already expired.
7. **VALUE_MISMATCH** := `transcript.value != transcript.invoice.amount`.
   The `.d.ts` gloss "note value proven" cannot fail independently of
   BAD_PROOF because the leaf binds the value — candidate spec bug.
8. **CAP_EXCEEDED**: strictly greater than `capLimit`; spend at exactly the
   cap is allowed.
9. **Cert failures**: signature that does not verify against the cert's own
   `issuer` → `BAD_SIGNATURE`; broken linkage (issuer is not the presented
   parent, wrong role, carver not the member cert's subject) →
   `BAD_CERT_CHAIN`.
10. **ReconcileTracker**: transcript identity is canonical bytes (a deep
    clone is byte-identical); invalid submissions **throw** an `Error` whose
    message contains the matching `VerifyResult` reason code; conviction
    `transcripts` = `[original accepted, current submission]`; `victims`
    grow in submission order.
11. **generateKeyPair seed mapping**: deliberately unpinned (determinism and
    point validity only) — which is why fixtures and goldens use literal
    key pairs.
